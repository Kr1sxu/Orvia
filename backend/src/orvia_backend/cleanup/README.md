# M17 当前用户临时文件隔离

M20自然输入“清理旧临时文件”仍只调用本模块固定范围扫描、逐项原生批准和同卷隔离/恢复，不接受文本中的任意清理根、不扩展永久删除。候选计划、取消、真实账本和核验结果在对话内呈现；只有当前计划实际moved/verified后该自然步骤才完成，重启不重放或把旧批准用于新任务。合成Temp流程、开发/安装边界与不支持任务在根PROGRESS独立记录。

## 用途、结构与接口

`service.py` 的 `CleanupService` 实现 `chat.cleanup.scan/plan/execute/restore`。仅 Windows 当前账户 `%LOCALAPPDATA%\Temp` 顶层、超过 30 天、独立普通 `.tmp/.log` 文件进入候选；不递归，最多观察 500 项、列出 50 项、合计 100 MiB、单项 10 MiB。路径由 Windows 当前账户已知文件夹取得，请求不能指定清理根。拒绝链接、联接、硬链接、占用文件、系统目录和注册表；不读取其他文件正文，也没有永久删除接口。

`scan` 在 SQLite 留下逐项文件名、大小、修改时间、风险、SHA256/身份与计划 revision。UI 逐项选择，主进程显示所选数量、大小和版本并原生确认；`execute` 再核对根、白名单、年龄、占用及身份，先记 `moving`，再同卷移动至 `%LOCALAPPDATA%\Orvia\cleanup-quarantine` 并验哈希。失败保留 `skipped/uncertain`，中断不自动重放。`restore` 在扫描后 30 天内按账本移动回原位置；原名冲突、隔离内容变化或期限过期时拒绝。到期隔离文件仍保留，本模块不自动清空隔离区。

输出区分候选逻辑大小、已隔离量和实际释放空间；同卷隔离的释放空间始终为 0。此流程不属于 M04 最近任务撤销，恢复由专门接口和原生确认完成。风险“低/中”按扩展名粗分，不能保证文件已经无用；执行前仍需用户逐项判断。中断或外部进程抢占引起的 `uncertain` 需人工检查 Temp 与隔离区，服务不会猜测后续动作。

## 依赖、运行、测试与示例

使用会话 SQLite、Computer `PathPolicy`、原生对话框和 Windows 文件系统；不调用模型，也不读取 `.env.local`。开发版在“系统清理”面板扫描，查看逐项风险和大小，选择并确认版本后隔离；需要时在期限内点“确认恢复”。不要把隔离显示为已释放空间。

定向 pytest 与 Electron E2E 命令见 `docs/PROGRESS.md` M17 节。测试只向 `artifacts/test-results/M17/` 下的合成 Local/Temp 副本注入测试根；未扫描或移动真实用户 Temp。系统空间、扫描时的外部更改、文件占用和不同 Windows 文件系统行为仍需真实环境谨慎试用；本模块没有系统目录、注册表或永久删除能力。
