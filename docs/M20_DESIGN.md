### 3.1 目录递归与分页预算

用户已于本轮选择A，以下A为已确认预算；B/C保留为历史候选。

推荐 A：默认只扫描所选目录第一层；明确要求“包含子目录／所有层级／递归”才扫描子目录，默认递归深度3，明确更深时最高8层。单次最多访问5000项、10秒扫描总时间（含落盘和批次发送等待）、4MiB元数据快照；每个真实批次至多40条且12KiB，完整清单每页100条。达到时间、条数、字节或深度预算立即明示尚未扫描范围，拒绝项单列。背压等待有独立期限，不凭停顿虚构进度。

推荐理由：与“看看这里”最小读取范围一致；5000项沿用已有总量边界，延长工作时间避免新批次和持久化开销使旧2秒预算过早截断。完整快照不再被46KiB会话帧吞掉，分页读取的是同一不可变扫描结果，不重新扫描或暗中扩大权限。

- B：默认即递归3层，其余预算同A。子目录覆盖更快，但默认读取范围更大，需要目录选择说明明确展示。
- C：保守一级／明确递归最多3层，500访问项／2秒／512KiB，批次20条／每页50条。资源更低，大目录会更早截断。

“全部清单”仅指本次实际发现且已接受的全部条目，不声称全盘扫描。显示已访问、已发现、当前已展示、拒绝、深度边界和截断原因。扩展名分类明确为元数据分类，不能冒充正文理解。未知和无扩展名保留，不猜内容。

## 4. 请求与真实事件方案

固定自然语言发送入口接收会话UUID、请求UUID、用户文字及显式资料引用；不接收路径、解释器、方法名、命令或审批布尔值。后台返回有界类型化步骤、等待必要资料／澄清／预览／审批的事实。

请求状态拟为 `pending → running → waiting_input / awaiting_confirmation → running → completed / failed / cancelled / interrupted`。完成只由步骤真实终态和核验决定。接续身份一次性、限同一会话和连接；切会话使自动接续失效。重启把等待与未完请求标为interrupted，读取历史不恢复任何权限。

事件绑定协议版本、会话、业务请求、传输请求、流身份和递增序号，类型为 started、tool_status、scan_batch、model_delta、paused、completed、failed、cancelled。扫描批次先以事务保存条目和扫描状态，再持久增加序号并输出；二者不是同一事务。崩溃后仅读取持久事实，不重放旧事件或恢复授权。终态快照带最后序号，便于核对历史与已展示结果。SQLite失败不得继续呈现尚未落盘的成功数据。

stdio保持64KiB每帧，事件帧另有小预算；服务器专用有界写队列和单写者，主进程严格区分响应与事件，按业务身份过滤。渲染端固定订阅／解除订阅和确认接口；缓冲有字节／条数上限，慢消费等待或停止，不能无限增长。重复序号忽略，乱序只允许有界缓存；缺口超时停止并显式读取持久事实，不自动重发工具或模型。连接失败使授权和自动接续失效。

模型增量来自供应商SSE，处理跨UTF-8块、分行、空心跳、结束原因、工具参数及用量。仅用户可读answer的真实新增解码文本暂呈现为“生成中，引用待校验”；处理JSON跨块转义和Unicode，不把完整JSON定时切字。真实前缀与序号同次UPDATE先保存再输出，前缀≤16000字且JSON编码≤24KiB；失败／取消／暂停／重启后快照幂等恢复同流一条model_partial，消息ID保持，明确未核验／不可成品。公开stream不再携带重复正文，恢复不重放事件、模型或权限。全部claims和引用仍待最终完整校验；部分文本不能成为成功回答。结构化代码／计划未完整校验前不出现有效批准控件。

不因流更新设置焦点、不覆盖逐会话草稿；阅读历史保持滚动位置，仅已在底部时跟随。提供“查看最新结果”，保留IME候选确认与Shift+Enter。业务执行串行；历史只读与状态可以旁路，切换不会把事件写入新会话。
