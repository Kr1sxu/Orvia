## 产品交互方向（2026-09-28 用户确认）

最终产品以对话框为主要交互入口。参考图用于确定侧栏、欢迎页、输入框和会话布局；图中宣传文字、任务示例和功能入口不构成开发要求。

- 左侧提供新建对话、历史会话，底部提供设置；中央欢迎页提供 Orvia 品牌、输入框和少量已支持能力的示例提问。
- 用户提交需求后进入消息流，底部保留输入框；用户继续提问、补充约束或查看结果，不需要切换到技术验收面板。
- 目录授权、扫描进度、文件结果、整理计划、审批、执行与核验结果以对话内卡片呈现；文件列表、属性、空间统计和大文件明细按需展开或显示在详情侧栏。
- 模型与凭据、连接诊断放入设置，保留现有 safeStorage 和固定角色配置能力，不提供任意模型切换；Main、Computer、Browser 是后台协作角色，不设置可配置团队入口。
- “本地资料”仅作为当前会话的已授权目录或显式附件展示，不新增全盘扫描或独立资料管理平台。文件附件处理在 M13 验收前不显示为可用能力。
- **明确不做**：自动任务、定时任务、后台主动任务、技能广场、技能商店、插件市场、管家团队管理、促销活动、推荐内容信息流，以及参考图中的其他额外能力入口；不创建占位按钮或假功能页面。
- 自然语言、历史消息和模型输出均不能授予文件权限或代替动作审批。授权必须通过主进程目录选择与 Computer 校验；写操作必须针对明确计划版本审批。

目标流程：输入“看看这个目录有哪些大文件” → 对话内请求选择目录 → 主进程授权 → 展示真实扫描状态 → 结果卡片与可展开明细 → 继续对话。提出整理需求时，追加计划、审批、执行与核验步骤。

M09 保留为已完成的只读能力基础，其面板式界面不是最终产品形态；后续复用 gateway、Application 和 M03 契约，将现有结果迁入对话，不重复实现文件安全逻辑。
